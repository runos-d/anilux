# Матрица индексирования AniLux

Источник, проверяемый тестом: `backend/apps/seo/route_matrix.json`. В матрицу входят все production-маршруты Vue Router; `/__visual__/modals` существует только в development/visual mode. Новый frontend-маршрут обязан сначала получить политику здесь.

## Политика групп

| Группа | HTTP и canonical | Robots | Sitemap | Основание |
|---|---|---|---|---|
| `indexable_static` | 200, self-canonical | `index,follow` только при включённом HTTPS origin | Да | Стабильная публичная страница с самостоятельным содержанием |
| `indexable_when_public_and_substantial` | 200 только для существующей и доступной сущности; legacy ID/slug даёт один 301 | `index,follow` после порога содержательности, иначе `noindex,follow` | Только indexable canonical | Публичные аниме, хабы, франшизы и проверенный UGC |
| `noindex` | 200 для app route; отсутствующая публичная сущность — 404 | Всегда `noindex,follow` | Нет | Авторизация, персонализация, токен, администрирование, интерактивная или тонкая страница |
| `canonical_redirect` | Один постоянный 301 на существующий canonical | На конечном URL | Только конечный URL | Исторические aliases и клиентские preset-маршруты |
| `not_found_in_production` | Настоящий 404 | `noindex,follow` | Нет | Catch-all и visual-only route |

`/people/:id` дополнительно существует только при `FEATURE_DUBS_ENABLED`; иначе Django и Vue одинаково возвращают 404. `/announcements/:slug`, `/people` и `/people/:id` сознательно остаются noindex: их качество и стабильность не гарантируют самостоятельную поисковую ценность. `/app`, `/donate`, `/roulette`, списки ленты/новостей/плейлистов также остаются noindex до отдельного продуктового решения; детальные публичные плейлисты и публикации индексируются только после порогов.

Удалённые и скрытые сущности сейчас дают 404. Код 410 не используется: в моделях нет достоверного публичного tombstone, который отличал бы окончательное удаление от скрытия. Изобретать такое состояние нельзя.

## Query-параметры

- Только `page=N`, где `N > 1`, может входить в canonical индексируемого листинга.
- `page=1` удаляется одним 301; preset query из redirect при этом сохраняется.
- `utm_*`, `gclid`, `yclid` не меняют canonical и удаляются при любой URL-нормализации.
- Поиск, сортировка, фильтры, размер страницы, shuffle, `section` и персональные исключения дают `noindex,follow` с canonical на базовую страницу.
- Неизвестные и повторяющиеся параметры не создают индексируемый URL; некорректная или повторная пагинация даёт 404.

## Приватность и статусы

Приватные публикации, закрытые группы, link/private плейлисты, invite/shared URL, кабинет, настройки, уведомления, история, библиотека, чаты и admin никогда не попадают в sitemap или JSON-LD публичной сущности. Неизвестный маршрут и отсутствующая сущность возвращают настоящий 404 без canonical и entity schema. Индексация всего сайта включается только явным `SEO_INDEXING_ENABLED` вместе с внешним HTTPS origin.
