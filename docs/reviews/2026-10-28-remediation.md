# Исправления по ревью 28 октября 2026

Исправлены R01–R26 из исходного отчёта, а также перечисленные там проблемы неподключённых настроек и документации. Уже существовавшие изменения рабочей копии сохранены. Коммит и развёртывание не выполнялись.

## Реестр исправлений

| Пункт | Реализация и проверка |
|---|---|
| R01 | Публичный AnimeViewSet теперь ReadOnlyModelViewSet. POST/PUT/PATCH/DELETE не доступны гостю или обычному пользователю. |
| R02 | Устаревшая HTTP-выдача общей realtime-очереди закрыта ответом 410; защищённый WebSocket остаётся штатным транспортом. |
| R03 | Общая privacy-проекция для User/PublicUser/UserSimple; поиск отдаёт компактный публичный DTO. Фото выдаются через проверяющий политику endpoint; старые media URLs также защищены. nginx больше не раздаёт avatars напрямую, PWA не кеширует их. |
| R04 | Email, телефон и служебные флаги исключены из записи обычного профиля. Подтверждение нельзя выставить PATCH-запросом; неподтверждённая подмена email заблокирована. |
| R05 | JWT привязан к серверной сессии через непрозрачный идентификатор. Отзыв устройства запрещает access, refresh и дальнейшую WebSocket-авторизацию. Поддержаны legacy JWT через token_version. Секрет Django session cookie не выдаётся в JWT/списке сессий. Logout работает и для клиента без cookie; смена пароля отзывает старые credentials и выдаёт новые текущему устройству. |
| R06 | Физические файлы удаляются после пакетной проверки оставшихся ссылок во всех FileField/ImageField того же хранилища. Пересланные файлы другого пользователя сохраняются. |
| R07 | Серверная команда пересылки проверяет allow_message_forwarding автора. |
| R08 | Detail новости применяет is_published для неадминистраторов. |
| R09 | Исправлен character class нормализатора; английская s сохраняется. |
| R10 | Поиск отменяет предыдущий запрос, проверяет поколение ответа и снимает таймер при dispose. Очистка не допускает возврата старых подсказок. |
| R11 | Плейлист открывается через именованный маршрут playlist-detail. |
| R12 | Hero загружает расширенные данные только текущего слайда, не всего списка; уже полученные данные повторно не запрашиваются. |
| R13 | Гостю не запрашивается приватное избранное. Загрузка начинается после подтверждённого входа; broadcast сообщений разделён по владельцу. |
| R14 | Новый просмотр из hero начинается с первой серии. |
| R15 | check_anime возвращает полную запись конкретного аниме. Плеер и CollectionButton используют её, не ищут аниме на первой странице библиотеки. |
| R16 | Activity tracker имеет явный идемпотентный start/stop. Старый tracker и таймер сохранения позиции снимаются перед сменой тайтла и при unmount. |
| R17 | WatchProgress store очищается при смене аккаунта; локальные позиции имеют ключ с владельцем. Отложенное сохранение позиции проверяет владельца. |
| R18 | Consent хранится отдельно для гостя и каждого аккаунта. Согласие другого пользователя не PATCH-ится на новый аккаунт; одинаковые решения не создают повторную запись. |
| R19 | Выбор в баннере и настройках проходит через единый lifecycle consent и синхронизируется с текущим аккаунтом. |
| R20 | Storage event применяет изменение consent в других вкладках, включая отзыв, без обратной записи того же решения каждой вкладкой. |
| R21 | Поиск использует компактную проекцию с нужными select_related. Проверка: 2 SQL и для одного, и для десяти результатов. |
| R22 | Используется корректный NotFound; несуществующий профиль даёт 404. |
| R23 | Calendar alias получает исходный HttpRequest. |
| R24 | Аватар автора новости читается только при наличии файла и разрешении политики; отсутствие аватара больше не даёт 500. |
| R25 | Свежий cached read не запускает GET. Invalidation и истечение 60 секунд по-прежнему обновляют данные. |
| R26 | PATCH приватности выполняются последовательно со снимками. Подтверждённое состояние берётся из ответа, устаревшие/закрытые экраны не запускают следующие сохранения. |

## Дополнительные замечания из приложения к ревью

- Смена пароля и просмотр/отзыв сессий доступны в SettingsView. Исправлен контракт пароля (current_password и совместимый old_password), подтверждение нового пароля, форма и вывод кнопки. Для сессий используется серверный признак текущего устройства.
- Хранилище показывает реальные агрегаты сообщений, вложений, файлов и временного кеша с единым DTO. Старые формы с фиктивными переключателями и обещаниями удаления сообщений заменены рабочим интерфейсом временного кеша. Неподдерживаемые destructive категории сервер отклоняет.
- Очистка действительно удаляет временный каталог текущего пользователя и публичные кеши устройства; история и сообщения не затрагиваются. Удаление пользовательских данных остаётся отдельным подтверждённым workflow.
- PUT настроек синхронизации сохраняет валидируемую модель SyncSettings. POST больше не утверждает, что несуществующий фоновый процесс выполнен: возвращает 409 с объяснением автоматического сохранения. Новый фоновый синхронизатор не создавался.
- «Помощь» ведёт на стабильную страницу /contacts вместо фиксированного ID чужого приватного чата.
- F0005/F0007 исправлены: lint не меняет исходники, lint:fix меняет; CI workflow существует.

## Применение

Добавлена миграция **users.0014_token_version_profile_storage** после уже существующей 0013. Её нужно применить до запуска обновлённого backend:

```powershell
python manage.py migrate
```

При доставке нужны также обновлённые frontend/nginx и service worker: иначе старый nginx продолжит прямую раздачу прежнего пути avatars. Новые серверные URL фото уже проверяют доступ самостоятельно. Перезапуск backend/worker и доставка нового frontend выполняются штатным процессом проекта.
