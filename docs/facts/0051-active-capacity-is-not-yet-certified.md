6000 активных пользователей не подтверждены: после первоначальных оптимизаций короткая ступень 120 пользователей/240 WS, 10 HTTP/с и 1 send/с прошла p95 <1 с, но при 30 HTTP/с и 2 sends/с вырос backlog доставки. Открытые sockets и microbenchmarks не являются доказательством устойчивого онлайна. Условия, исходные данные, исправления и незакрытые критерии: `docs/reviews/2026-10-29-capacity-review.md`; remote deployment не выполнен.

Владелец уточнил: несколько комнат на тысячи участников, комнаты на сотни; общие оптимизации без чрезмерной сложности важнее прежнего бюджетного ориентира 10 000 ₽. Дополнительный проход устраняет повторную загрузку TLS CA на каждом DB connection (D0032), глобальную сериализацию независимых WS DB readers/commands, roundtrips для пустых Redis groups и суточное хранение членства погибших сокетов (D0031). Активные подписки продлеваются heartbeat, default group expiry 300 с; при rolling upgrade нужен двухэтапный переход TTL. Эти исправления сами по себе не сертификат ёмкости.

Позднее владелец расширил цель до максимальной масштабируемости всех активностей, потенциально миллиона одновременных пользователей. Предложение стека и этапов: `docs/SCALABILITY_ROADMAP_2026-10-29.md`; это план, а не внедрение или подтверждённая ёмкость.

В рамках частичной реализации roadmap подготовлен отдельный production-build lab с синтетическими данными и независимым observer. При 120 users/240 WS, 10 HTTP/с, 1 send/с, 60с на четырёх API доставлено 7200/7200 событий, HTTP p95/p99 184/276мс, chat 982/1313мс. Smoke p95 ≤1с пройден, предложенный roadmap chat SLO 500/1000мс — нет. На двух API тот же профиль получил 6688/7200 доставок в окно и chat p95 18,808с. Это общий Docker Desktop, без full-domain workload/soak/reconnect/host failover; 6000/миллион по-прежнему не подтверждены. Владелец подтвердил доступность только локальной среды. Состояние этапов: `docs/SCALABILITY_PROGRESS.md`; воспроизводимые результаты: `docs/reviews/2026-10-29-scalability-evidence/README.md`.

Продолжение подтверждает ограничение: после multicast/index короткий 120/4 API профиль достиг 598/791мс, но 300с дали chat 5998/8177мс при всех 36000 доставках; acceptance FAIL. 8 API/60с дали 714/1079мс, строгий SLO также FAIL. Неуспешные reader experiments откачены и сохранены; ACK/command phases измеряются отдельно. Evidence: `docs/reviews/2026-10-29-scalability-continuation-evidence/README.md`.
