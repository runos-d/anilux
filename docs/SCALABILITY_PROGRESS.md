Рабочая ветка: `codex/scalability-roadmap`. Основание: [roadmap](SCALABILITY_ROADMAP_2026-10-29.md), D0031, D0032, F0051. Production не переключается. Ни одна ступень онлайна пока не сертифицирована. Дата начала: 2026-10-29.

## Журнал результатов

- Исходное состояние: чистый `main`, `102b9cb`; `origin/main` после fetch совпадает. Создана рабочая ветка. Реальная `.env`, данные и локальные пользовательские контейнеры не используются для нагрузки.
- Новые результаты и команды добавляются вместе с проверенными изменениями; исторические evidence не перезаписываются.
- Первая поставка: опциональная ASGI telemetry с bounded labels/private scrape, независимые cache/Channels Redis URL и bounded cache connection pool; отдельный production-build Compose, синтетический seed, HTTP-генератор и snapshot outbox/DB/queue; профили всех доменов. Проверено: 7 новых unit/config/safety tests, Django check (0 issues), Compose config, backend/frontend Docker build. Frontend baseline: 91 files / 284 tests PASS; types, lint, analytics architecture, build/bundle PASS (JS 148227, CSS 70960 bytes). Полная миграция пустой MySQL ещё выполняется; HTTP load и backend domain regressions будут записаны отдельно. kms CLI в окружении отсутствует: knowledge records/индексы обновлены вручную по принятому формату.
- Этапы 2/3: холодное персональное чтение рекомендаций использует общий неперсональный fallback, worker готовит личную проекцию; dirty-проекция не возвращает старые причины из очищенной истории. Live исключения библиотеки/видимости ограничены кандидатами (не всей коллекцией). Catalog invalidation повышает revision и не позволяет уже работающему worker опубликовать устаревший результат. `rebuild_recommendations` делает bounded keyset recovery с dry-run по умолчанию. 6 новых регрессий входят в прошедший целевой MySQL-набор: 54 tests PASS (рекомендации/календарь/chat extensions/oct12). Бесконечная персональная библиотека ещё может дорого обрабатываться фоновым алгоритмом; online путь её больше не материализует.
- Этап 5: приватные chat/post fallback responses используют async iterator по 64 KiB вместо синхронного iterator, который Django ASGI мог целиком буферизовать. HEAD/Range/416 ограничены; на каждый новый fetch сохраняются исходные текущие ACL, tickets, prejoin/clear и bans. X-Accel постов сохранён. 4 streaming/range unit tests PASS; chat extensions и video cache входят в 54 PASS выше. Исходный общий прогон: 272 tests / 24 filesystem errors из-за владельца нового lab volume; после разделения test media/tmp — 276 tests / 4 ошибки только sync-потребления async iterator в тестах. Тесты переведены на native async consumption; SQL/transaction connection тестов при чтении stream не закрывается. Новый целевой прогон PASS. Полный повтор будет сохранён отдельно.
- Этап 2, лента: following/group membership остаются SQL subqueries вместо материализации всех ID в Python. Для mutable рейтингов курсор хранит максимум 200 подготовленных ID, а последующие окна продолжаются keyset; текущая видимость перечитывается при hydration. Это не полный снимок всей ленты: далеко за окном порядок по изменившимся счётчикам может обновиться. Исправлена старая регрессия пропуска ещё не просмотренного поста внутри окна после изменения реакций. 45 site-rebuild tests PASS, включая 230 постов за пределами окна, cursor owner и privacy change. Общий набор проверил 333 теста: 332 PASS, одна ошибка нового fixture (`bulk_create` MySQL не возвращает auto IDs); после исправления только fixture все 45 соответствующих тестов PASS.
- Этап 4: isolated queue profile — opt-in, legacy остаётся default; отдельные events/media/imports/reports workers, маршруты notifications/recommendations/maintenance; RabbitMQ quorum + confirm + deadlines + bounded overflow/DLQ, pre-provisioning до workers и совместимые exclusive control/event queues. Countdown retry, stopped broker → persisted SQL/outbox → restart/recovery → duplicate task прошли. Применена lab at-least-once dead-letter policy. Centrifugo 2 nodes + официальный SDK: 1200/1200 synthetic deliveries, p95 32мс, p99 50мс; current-session delivery check не реализован, protected migration **не включена**. Брокер/transport HA и полный функциональный replay ещё открыты. Подробности: `deploy/scalability/BROKERS.md`.
- Этап 5, S3: optional migration-worker SDK/lock и `mirror_media_file`: dry-run без сети, content addressing, bounded multipart upload/readback SHA-256, проверка неизменности источника, private fsync manifest вне checkout. Источник и live paths не меняются; публичная выдача не включается. 3 mock/dry-run/corruption/path tests PASS, optional image собран. Реальный S3/CDN, инвентаризация всех путей, dual-read/write и live cutover **не выполнены**. Подробности: `deploy/scalability/OBJECT_STORAGE.md`.
- Этапы 1/6/7: добавлены SQL и fresh WS batch counters, фазовые outbox timings, bounded authenticated/mixed probes, collector ресурсов/исходников/images/queue backlog и label-guarded backup/restore rehearsal. Новый пустой MySQL мигрирован полностью; model drift не найден. Restore: synthetic dump 5751305 bytes, 71,984с, counts/checksums 6 tables совпали. Browser production recommendations: authenticated profile 200, desktop/390px без page/console errors и horizontal overflow. Предыдущие init failures оказались frame cap тестового клиента: snapshot 66398 bytes превышал 64 KiB; response budget поднят до bounded 1 MiB, server incoming limit не менялся.
- Последний завершённый mixed probe (до финального collector packaging): 12 users/24 WS, две комнаты по 6 активных из 60; 5 HTTP/s + 1 send/s, 20с. 100/100 HTTP 200, 20/20 ACK, 240/240 unique deliveries; duplicates/unexpected=0. HTTP p95/p99 618/1281мс, delivery 1508/2422мс. Порог **не пройден**. Queue/worker phase обычно ~0,05–0,17с, значит требуется измерять post-publication authorization/projection/scheduling; кешировать доступ нельзя. Это общий Docker Desktop, не production host. User подтвердил: внешняя инфраструктура отсутствует, работа ограничена локальной средой.
- Исправление observer: первоначальный collector запускал Django probe внутри CPU-quota API, сам искажал нагрузку (в этом прогоне scheduler p99 генератора 126мс, missing ACK/delivery в окно). Optional S3 image: pip check и фактический TransferConfig SDK PASS. Ступени с независимым observer: 12 clients / 2 API / 20с — p95 HTTP 87мс, chat 365мс, 240/240 deliveries; 120 clients / 2 API / 60с — 6688/7200 в окно и p95 chat 18,808с, FAIL; 120 clients / **4 API** / 60с — 600/600 HTTP, 60/60 ACK, 7200/7200 deliveries, p95/p99 HTTP 184/276мс, chat 982/1313мс. Последний прошёл smoke, **не предложенный roadmap SLO chat 500/1000мс**. Это разные cgroup-конфигурации на общей машине, без коэффициента ускорения или сертификата capacity. После основного набора 334 PASS добавлены static inventory и дополнительные isolated routes: 7 targeted checks PASS; actual Celery router совпал с картой всех 88 tasks, unregistered beat tasks нет. Legacy default/ACL/delivery pipeline не менялись. В опубликованных manifests удалён только hash одного ignored-конфига, факт фильтрации отмечен; исходные local evidence сохранены. ## Продолжение: фазовая диагностика

- Фактический старт: чистая `codex/scalability-roadmap`, HEAD и origin `79749ce`; `main`/origin main `102b9cb`. Только локальная среда, сохранённые synthetic volumes.
- Реализовано: ограниченные post-publication histograms по transport/consumer, batch/executor wait, MySQL connection/SQL, DTO preparation/serialization и ASGI send. Timestamp остаётся внутренним; D0031/CONN_MAX_AGE=0 сохранены. Collector хеширует все tracked backend Python sources и сохраняет exit code; mixed probe отмечает load window, phase summarizer проверяет resets/membership и исключает ramp.
- Проверено: 22 telemetry/session/TLS tests (0,559с), 72 chat projection/isolation/conversation regressions (173,021с), isolated MySQL. Capacity/SLO по этой инструментированной версии ещё не заявлены.

- Продолжение realtime: bounded union текущих user groups уменьшает число transport frames/process; native Channels receiver/dispatch и D0031 сохранены. Реальный Redis проверяет capacity/expiry/dedup/изоляцию; сессия и membership отозваны после первой успешной multicast-доставки, повтор старого event не раскрывает payload. 63 targeted regressions + 5 real Redis/security tests PASS. Сопоставимый 120/4 API профиль: HTTP 154/239мс, chat 681/895мс, 7200/7200, против instrumented baseline 3190/3880мс. Smoke PASS; p95 500мс ещё открыт. [Новый evidence](reviews/2026-10-29-scalability-continuation-evidence/README.md).

Медиа продолжены независимо: `inventory_media_page --describe` и bounded private FileField pages с keyset/watermark/status и 0..64MiB hashing/page. Четыре regression tests PASS: границы/cursor/new writes, hash budget, missing/invalid paths, exclusive manifest/checkout/symlink protection и отсутствие SQL в describe. Это подготовка migration inventory; JSON/exports/orphans, dual-read/write, live S3/CDN остаются открыты.

- SQL продолжение: social.0039 покрывает unread scan; plain projections читают только viewer IDs, rich получает текущие accounts. 75 regression tests PASS (29,775с), MySQL EXPLAIN покрывающий, drift отсутствует. 120/4 API/60с повтор: HTTP 150/196мс, chat 598/791мс, 7200/7200; p95 500мс открыт. Точный unread всё ещё зависит от длины истории; это не готовая асинхронная счётчиковая проекция.

## Следующая работа

1. Фазовая диагностика выполнена; продолжить ограничение стоимости точного unread на длинной истории и снизить chat p95 до 500мс на повторяемом профиле. Эксперимент удаления дополнительного ACL callback не улучшил p95 (615 против 598мс), сохранён и откачен; текущий ACL pipeline прежний.
2. Расширить фиксированные datasets/профили на rich messages, тысячи участников, действия read/typing/edit/delete/replay и остальные домены из workload map. Только после этого повышать пользователей/RPS и длительность.
3. Продолжить открытые реализации этапов 3/5/6 из таблицы. Без внешних host/storage провести только локальные совместимые изменения; S3/CDN, DB/broker HA и большие load stages принять на отдельной инфраструктуре.

Проверено дополнительно: функциональные reconnect/5 offline messages/4 rich replies/idempotent duplicate/current edit-delete replay/cross-room denial. Генератор теперь допускает bounded 1..1800с только с `--soak`, отдельно отражает предложенный SLO, проваливает duplicates/closures. Длительный acceptance ещё требует выполненного прогона; mass reconnect/большие rich rooms остаются открыты.
